# 创新点

> 一句话：把“群里的一句话”变成“经过群体时间/空间/权限校验、可保存执行的活动”，并用 Trace 留下可审计证据。

## 1. 共享地图作为“群体空间记忆”

不是把地点塞进一次对话上下文，而是把地点、备注、评论、群聊沉淀为可检索的群体资产。Agent 的 `get_group_map_context` / `search_group_map_places` 直接读这份资产，站点来源由后端按地图成员关系盖章，模型不能自称“来自共建地图”。

证据：`GroupMapContextService`、`PlanItineraryAcceptanceTest`、`tools/eval` S1/S4。

## 2. LLM 只做编排，确定性求解器判可行

LLM 负责理解意图、选候选、组织语言；共同空闲由 `FreeWindowSolver` 计算，站点顺序/停留/交通由 `SpatiotemporalPlanner` 求解，`PlanValidator` 做时间、交通三态、权限硬校验。模型自述的 `routeConfidence` 会被清空重算。

证据：`SpatiotemporalPlannerTest`（含 50 次重复确定性用例）、`PlanValidatorTravelCheckTest`、`AgentToolkit.planItineraryTool`。

## 3. 隐私边界：未授权不等于有空

FREE_BUSY 只暴露时段不暴露标题；未授权成员进入 `UNKNOWN`，方案降级为 `TENTATIVE`，而不是假设其空闲。群规划公开摘要只返回白名单字段；私有站点坐标/备注不出群；群聊 AGENT 文本与 GEO 帧在第四轮增加了二次过滤。

证据：`ScheduleAcceptanceTest.groupBusyRespectsFreeBusyGrants`、`GroupPlanSharingAcceptanceTest`、`GroupAgentPayloadFilterTest`、`tools/verify-round3-scenarios.mjs`。

## 4. 从草稿到活动的可信执行

保存不是“把 JSON 写库”：行锁 + 版本防覆盖 + 群体二次校验（成员/地图/指纹/日程变化）+ 交通硬校验；失败返回 409/400 并给出可执行修正；重复保存复用同一 activityId。

证据：`PlanSaveConcurrencyAcceptanceTest`、`PlanSaveGroupRevalidationAcceptanceTest`、`PlanReviseAcceptanceTest`、S6。

## 5. 可审计的 Agent 执行证据

Trace 在真实执行点埋点（LLM/工具/路线/忙闲/草稿/校验/保存），脱敏后异步写入，支持 JSONL 导出与 p50/p95。第四轮把 `run/metrics` 写入 Trace，使 Token/轮次/缓存/首字延迟可被评测脚本重复采集。

证据：`docs/agent-trace/`、`TraceCenterView.vue`、`docs/验收记录/第四轮_评测报告.md`。

## 与“普通 AI 聊天 + 地图”的差异

| 维度 | 普通方案 | 本项目 |
|---|---|---|
| 地点 | 模型自由生成 | 共建地图工具 + 后端来源盖章 |
| 时间 | 模型估算 | FreeWindowSolver + 真实路线耗时 |
| 可行性 | 事后人工发现 | PlanValidator 硬校验 + 可执行错误 |
| 隐私 | 把成员日程塞进 prompt | FREE_BUSY / UNKNOWN / 公开摘要白名单 |
| 执行 | 只给文本 | 草稿→活动，行锁/幂等/409 |
| 证据 | 聊天记录 | Trace + JSONL + 量化评测 |
