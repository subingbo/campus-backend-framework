# 可靠性设计

## 聊天幂等

`clientMsgId` + 唯一键 `(conversation_id, sender_id, client_msg_id)`；服务端先查/后插，重复只回 `CHAT_ACK duplicate=true`，不 fanout、不触发群 AI。客户端 outbox 按用户存 sessionStorage，收到 ACK 才出队，重连带同一 id 重发。

图：`diagrams/09-chat-idempotency.mmd`。

## 通知收件箱

- `notification` 唯一键 `(user_id,dedupe_key)`；单 INSERT，冲突即 `created=false`，不重复推送。
- 业务数据与通知行同一事务；`AfterCommit` 只在真实事务提交后推送 WS。
- WS 是尽力投递；离线/崩溃后从 `/messages` 收件箱查，不重放实时帧。
- 总角标 = 未读通知 + 有未读会话数；好友申请/活动邀请只做 tab 待办。

图：`diagrams/08-message-center-reliability.mmd`。

## Trace

- 真实执行点埋点；脱敏后异步有界队列写入；`seq` 行锁保证同会话唯一。
- 队列满/写入失败降级，不影响主业务；`complete/pendingEvents/droppedCount` 可查。
- 第四轮新增 `run/metrics`，把 Token/轮次/首字延迟/路线缓存差量写进 Trace，评测可重复采集。

图：`diagrams/10-trace-pipeline.mmd`。

## 并发与保存

- 活动报名/接受邀请锁活动行；签到/取消报名原子条件删除。
- 保存草稿行锁 + `expectedPlanVersion`；重复保存幂等；群体二次校验失败 409。
- 群 AI 同群单飞、runId 取消；线程池有界，队列满 BUSY。

## 明确边界

- 单实例；多实例需要 Redis Pub/Sub/网关粘性/分布式锁。
- 聊天未读只在 Redis；无 DB 已读表。
- 客户端 outbox 关闭标签页会丢未 ACK 消息。
- 真实 LLM/高德失败时降级/报错，不伪造成功。
