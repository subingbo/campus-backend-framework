# 系统架构

## 组件与协议

- `campus-web`：Vue 3 + Vite；HTTP REST、SSE（个人 AI 流式）、WebSocket（群聊/群 AI/Trace 状态）、静态地图。
- `campus-server`：Spring Boot 3.5 / Java 21；Controller → Service → MyBatis；按业务分包（auth/map/place/activity/schedule/social/ai/notification/trace）。
- `campus-framework`：JWT、Security、统一 Result、限流、Redis 配置。
- MySQL 8：33 张表，业务状态唯一 Source of Truth。
- Redis 7：refresh token 白名单、路线缓存、未读、限流、在线态。
- DashScope：qwen-plus（OpenAI 兼容 function calling）。
- 高德 Web 服务：真实路线/POI；失败降级 `estimate` 并标记 `estimated=true`。

渲染图：`diagrams/01-system-architecture.mmd`、`02-module-dependency.mmd`。

## 关键数据流

1. **个人助手**：`/assistant` SSE → AgentService 14 轮/5 工具/6 次搜索预算 → `submit_plan` → PlanValidator → PlanSaveService。
2. **群 @AI**：WS `CHAT_SEND @AI` → GroupAgentService 单飞/runId → AgentService（群语境）→ AGENT 消息 + 快照同事务 → `AGENT_PLAN_CARD`。
3. **通知**：业务事务内 `notification` 唯一键写入 → afterCommit WS → `/messages` 收件箱兜底。
4. **Trace**：真实执行点 → 脱敏 → 有界队列 → `agent_trace_session/event` → Trace Center/JSONL。

## 分层边界

- 地图厂商只出现在 `TravelInfoProvider`/前端地图适配层；Spring 业务与数据库不绑定高德 SDK（见 `layered-capability-preference` 约定）。
- `PlanValidator` 是草稿进入业务库前的唯一硬校验入口；LLM 输出、前端编辑、群卡片都不能绕过。
- 群规划公开摘要走 `GroupPlanPublicView` 白名单，不直接序列化 `PlanDto`。

## 部署形态

当前是单实例：WS 会话/群 Agent 运行注册表/Trace pending 计数都是进程内。多实例需要 Redis Pub/Sub 或网关粘性；详见 [部署与运维](../部署与运维.md)。
