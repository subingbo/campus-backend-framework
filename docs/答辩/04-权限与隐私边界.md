# 权限与隐私边界

图：`diagrams/06-permission-boundary.mmd`

## 已实现的硬边界

| 数据 | 规则 | 测试 |
|---|---|---|
| 私人/受限地图 | `map_member` 实时校验；非成员 403；被移出群后群规划 403 | `SharedMapAcceptanceTest`、`GroupPlanSharingAcceptanceTest` |
| 他人日程 | FREE_BUSY 只返回时段，标题/备注恒为 null；未授权 -> UNKNOWN | `ScheduleAcceptanceTest` |
| 群规划摘要 | 只投影 `GroupPlanPublicView`；私有站点 `locationVisible=false` 且坐标/placeId 清空 | `GroupPlanSharingAcceptanceTest` |
| 群聊 AGENT 文本/GEO | 第四轮新增 `GroupAgentPayloadFilter`：丢弃 PERSONAL_MAP/USER_LOCATION、独立路线事件；文本替换私有站点名 | `GroupAgentPayloadFilterTest` |
| 通知 payload | `NotificationPayloadPolicy` 只允许路由键；不含签到码/标题/备注/坐标 | `NotificationPayloadPolicyTest`、`NotificationAcceptanceTest` |
| 签到码 | 仅创建者可见；成员/旁观者 null | `ActivityCheckinAcceptanceTest` |
| Trace | 仅本人；list/detail/events/export 均按 user 过滤；脱敏 | `TraceDataRedactorTest`、`AgentTraceFlowAcceptanceTest` |
| 群规划 handoff | 仅发起人 | `GroupPlanSharingAcceptanceTest` |

## 已知边界（本轮不假装解决）

1. **全局地点库语义**：地点写入后是全局 `place` 行；知道/搜索到私密图里的地点仍可能读到名称/坐标。第四轮选择保留该产品语义，不做地点级 ACL。
2. **活动 stops**：活动详情目前不按来源地图做成员级过滤；若活动包含私密来源站点，登录用户可能看到坐标/备注。作为下一轮产品决策。
3. **多实例**：WS/群 Agent 注册表是进程内；多实例实时推送与单飞不成立（见部署文档）。
4. **持久化已读**：会话未读只在 Redis；清 Redis 后已读状态不可恢复。

## 答辩口径

- 可以说“群规划卡片、群 AI 输出、通知 payload、Trace、签到码有明确负向测试”。
- 不要说“所有地点/活动数据都做了 ACL”；应说明“全局地点库是当前产品语义，地点级 ACL 是后续工作”。
