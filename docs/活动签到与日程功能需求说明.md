# 活动签到与日程功能 · 需求说明

> **口径提示（2026-10-22）**：签到窗口以代码为准：**开始前 15 分钟至开始后 15 分钟**（`CHECKIN_WINDOW=15`），本文早期“开始时刻起”的表述已过期。最新流程见 [`项目全流程说明.md`](./项目全流程说明.md)。

> 2026-10-14 起草并一期落地。场景：用户在地图上点开一个地点（食堂、球场、楼馆），
> 在该地点安排活动（开会、约球、比赛召集），其他用户报名参加；现场用数字签到码完成
> 签到并留下记录；一个独立的活动日程页查看「我的日程」并接收开始提醒。

## 1. 功能总览

| 能力 | 状态 | 说明 |
|------|------|------|
| 在地点上安排活动 | ✅ 已有创建，✅ 补齐编辑/取消/类型 | 会议 MEETING、比赛 COMPETITION、其他 OTHER |
| 报名/取消报名 | ✅ 已有 | 人数上限、结束前可报名、重复幂等 |
| 数字签到码签到 | ✅ 一期新增 | 创建时生成 6 位码，**活动开始前 15 分钟起**至 `checkin_open_until`（默认开始后 15 分钟）内可签；记录落在报名行上 |
| 组织者公布签到码 + 成员签到记录 | ✅ 一期新增 | 仅创建者视角可见完整码；成员/组织者可看谁已签、何时签 |
| 比赛召集邀请 | ✅ 一期新增 | 组织者向用户发出 `activity_invite`，对方接受后自动进成员，拒绝/重复有状态机 |
| 日程页（/activities） | ✅ 一期新增 | 我日程（今天/明天/未来 7 天/更远/已结束分组）、我创建的（签到码+成员记录）、收到的邀请 |
| 活动开始提醒 | ✅ 一期新增 | 定时扫描 + WebSocket 推 `ACTIVITY_REMINDER`（T-15 与 T-5 各推一次，Redis 防重） |
| 活动取消通知 | ✅ 一期新增 | WS 推 `ACTIVITY_CANCELLED` 给成员 |
| 召集邀请通知 | ✅ 一期新增 | WS 推 `ACTIVITY_INVITED` 给被邀请人；接受后推 `ACTIVITY_MEMBER_JOINED` |
| 编辑活动 | ✅ 一期新增 | 仅创建者；未开始时字段全可改，已开始后只冻结时间与行程（标题/描述/类型/人数仍可维护）；改开始时间会顺延签到窗口 |
| **月历视图（日历组件）** | ✅ 一期新增 | `/activities` 默认 tab 用 `el-calendar` 月历：格子按日聚合我的活动（phase 配色，多于 2 条折叠「+N 项」）；点条目弹活动详情，选中日下方列当日活动 |
| **活动详情（人员关联）** | ✅ 一期新增 | 详情含时段/类型/人数/发起人/描述/我的签到状态，可展开参与人员与逐人签到情况（复用 members 接口权限） |
| **"去现场"地点联动** | ✅ 一期新增 | 新接口 `GET /api/places/{id}/maps`：地点所在且我可见的地图；详情「📅 去现场」直达 `/maps/{id}?place={placeId}`，多张图先弹单选；工作台自动打开该地点活动面板 |

## 2. 数据模型（均为增量，不破坏已有数据）

```text
activity            # 见 db/schema.sql；新增列 category / checkin_code / checkin_open_until
activity_member     # 新增列 checked_in / checked_in_at —— 签到记录就落在报名行（uk_activity_user 保证一人一行）
activity_invite     # 新表：活动召集邀请（activity_id, inviter_id, invitee_id, status 0待/1收/2拒, handled_at）
```

注意：**没有单独的"签到表"** —— 一人一条报名记录即天然防重复签到，签到状态随成员关系走。

## 3. 接口清单（均在新版 Swagger UI「校园业务」分组内）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/activities | 创建活动（10 次/分钟/用户限流；返回创建者可见的 checkinCode） |
| GET | /api/activities/{id} | 详情（成员视角 checkinCode 恒为 null） |
| PUT | /api/activities/{id} | 编辑（创建者；字段可选；已开始时拒绝时间/行程变更） |
| DELETE | /api/activities/{id} | 取消（创建者；推 ACTIVITY_CANCELLED） |
| GET | /api/activities/mine?role=created/joined/all | 我的日程数据源 |
| GET | /api/activities/{id}/members | 成员 + 签到记录（成员或创建者可见） |
| POST | /api/activities/{id}/join | 报名（15 次/分钟限流） |
| DELETE | /api/activities/{id}/join | 取消报名 |
| POST | /api/activities/{id}/checkin | 输码签到（{code}；窗口内 + 对码；10 次/分钟） |
| POST | /api/activities/{id}/invites | 召集邀请（创建者；人数受名额约束） |
| GET | /api/activity-invites/pending | 我收到的待响应邀请 |
| POST | /api/activity-invites/{id}/accept | 接受（自动加入成员；名额满则拒绝） |
| POST | /api/activity-invites/{id}/decline | 拒绝 |
| GET | /api/places/{placeId}/activities | 地点活动列表（工作台抽屉用） |
| GET | /api/places/{placeId}/maps | 该地点所在、我可见的地图（日历"去现场"跳转用） |

WebSocket 帧（复用既有 `/ws` 管线）：`ACTIVITY_REMINDER {activityId,title,placeName,minutesLeft,summary}`、
`ACTIVITY_CANCELLED`、`ACTIVITY_INVITED {inviteId,...,summary}`、`ACTIVITY_MEMBER_JOINED`。

## 4. 提醒机制

- `ActivityReminderScheduler`：`@Scheduled(fixedDelay=60s)`，每次扫描 `[now-1min, now+30min]` 内开始的未取消活动；
  会在剩余 ≤15 分钟与 ≤5 分钟两个提前量各发一次提醒（Redis `activity:reminded:{id}:{offset}` SETNX+TTL 防重，
  重启/重复扫描不重发）。提醒通过会话注册表推给在线成员；被推送者不在线即丢（见「还差什么」）。
- 提醒文案含活动名、地点名与剩余分钟，前端直接弹 Element Plus toast。

## 5. 签到规则

1. 窗口：`start_time - 15 分钟` 起、到 `checkin_open_until` 止（默认开始后 15 分钟，创建/编辑时自动生成）。
2. 前提：已报名；错码/窗口外/未报名分别得到 400/400/403。
3. 幂等：重复提交对码签到返回成功但 `checkin_update` 只命中一次（`checked_in=0` 条件更新）。
4. 记录：`checked_in_at` 精确到秒，组织者在「成员/签到记录」里核对。
5. 取消报名：已签到成员不能取消报名（400「已签到，不能取消报名」），避免签到记录随成员行被硬删除。

## 6. 前端结构

- **地图工作台（MapWorkspaceView）**：地点抽屉新增「本地点活动」面板（列表/报名/签到/成员 inviting/创建/编辑/取消），手机端锚定浮窗同款入口；侧栏新增「活动日程」入口。
- **活动日程页（ActivitiesView，/activities）**：三个 tab；顶栏入口加在地图列表页与好友页；WS 帧在 onMounted 注册 toast + 自动刷新。
- 创建对话框复用既有 addDialog 模式；时间选择为 Element Plus `datetimerange` 弹层（鼠标点选后确认）。

## 7. 还差什么（二期清单）

1. **多实例部署的提醒可靠性**：在线注册表在内存、调度任务每实例各跑一份——多实例会漏推或重复推；
   需 Redis Pub/Sub 广播 + 调度分布式锁（ShedLock/Redisson）。
2. **离线提醒补偿**：现在不在线就收不到且无补投；需要 `activity_notice` 持久化表 + WS 重连后拉取未读。
3. **通知中心**：没有站内信收件箱、没有已读/未读徽标聚合（现有 UNREAD 帧前端也未消费）。
4. **手机端**：定位签到（到点核对距离）、日历导出（ICS）、厂商推送通道。
5. **活动组织体验**：周期性重复活动、活动图片、活动总结/相册、活动签到统计报表（未来可用于活动热度评分）。
6. **权限细化**：目前活动任意登录用户可查详情；如需"仅地图成员可报名/参赛"需在 join/checkin 前挂地图成员校验。
7. **日历增强**：周/天视图切换、**按人筛选日历**（看某好友参加什么——涉及成员列表隐私边界，需先设计可见性）、
   日历上直接拖拽改期（后端 PUT 编辑接口已支持，只差前端交互）、节假日提示。
8. **已知小怪癖**：后端 `NOW()` 与 Jackson 数组序列化的时区呈现不一（`joinedAt` 显示偏 UTC-8，见开发报告 10-06 条目），
   属既有序列化怪癖，展示层兼容数组即可；一期未改。
