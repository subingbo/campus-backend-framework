# 部署与运维（2026-10-22）

## 1. 依赖与启动

- MySQL 8、Redis 7；后端 Java 21 / Spring Boot 3.5；前端 Vue 3 + Vite 6。
- 本地：`docker compose up -d` 启动 MySQL/Redis；`mvn -pl campus-server -am spring-boot:run`；`npm --prefix campus-web run dev`。
- 生产：当前仓库不提供应用容器；需自行准备同源反向代理（前端静态资源 + `/api` + `/ws`），WebSocket 需要 Upgrade 透传。

## 2. 数据库迁移（必须按顺序）

全新库由 `db/schema.sql` 一次性建 33 张表；存量库必须手工执行以下 8 个脚本（`initdb.d` 不会对旧库重跑）：

```bash
mysql -u<user> -p <db> < campus-server/src/main/resources/db/migration/20261015_01__create_activity_stop.sql
mysql -u<user> -p <db> < campus-server/src/main/resources/db/migration/20261015_02__create_ai_tables.sql
mysql -u<user> -p <db> < campus-server/src/main/resources/db/migration/20261016_01__create_personal_schedule.sql
mysql -u<user> -p <db> < campus-server/src/main/resources/db/migration/20261018_01__add_ai_message_geo_json.sql
mysql -u<user> -p <db> < campus-server/src/main/resources/db/migration/20261019_01__create_agent_trace.sql
mysql -u<user> -p <db> < campus-server/src/main/resources/db/migration/20261022_01__add_message_client_msg_id.sql
mysql -u<user> -p <db> < campus-server/src/main/resources/db/migration/20261022_02__add_group_agent_plan.sql
mysql -u<user> -p <db> < campus-server/src/main/resources/db/migration/20261023_01__create_notification.sql
```

说明：
- 迁移 3/5/6/7 含 `ALTER TABLE`，不可重复执行；执行前先备份。
- `SchemaPreconditionChecker` 启动时检查多站行程、个人日程、AI 地图回放、Trace、聊天幂等、群规划快照、通知收件箱；缺失即 fail-fast 并给出迁移文件。
- 没有 Flyway/Liquibase；迁移版本需由部署方自行记录。

## 3. 环境变量与密钥

| 变量 | 必填 | 说明 |
|---|---|---|
| `DASHSCOPE_API_KEY` | 真实 LLM 必填 | qwen-plus（DashScope OpenAI 兼容） |
| `AMAP_WEB_KEY` | 真实路线必填 | 高德 Web 服务 key（不是前端 JS key） |
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | 生产必填 | 若覆盖 JDBC URL，必须保留 `connectionTimeZone=Asia/Shanghai&forceConnectionTimeZoneToSession=true` |
| `REDIS_HOST` / `REDIS_PORT` | 生产按需 | 默认 localhost:6379 |
| `CAMPUS_TIMEZONE` | 可选 | 默认 `Asia/Shanghai`；JVM 时区由 `campus.timezone` 设置 |

- 本地密钥放 `campus-server/src/main/resources/application-secrets.properties`（已 gitignore），或使用同名环境变量。
- 前端高德 JS key 放 `campus-web/.env` 的 `VITE_AMAP_KEY`（已 gitignore）。
- 生产不要使用仓库里的 `dev-only-change-me` JWT secret 和 `campus/campus123` 数据库账号；当前仓库没有 prod profile，部署方需通过环境变量/外部配置覆盖。
- `CorsConfig` 当前只允许 localhost 来源；前后端不同源部署时建议同源反向代理，或按实际域名修改 CORS。

## 4. 时区

- JVM 时区由 `campus.timezone`（默认 `Asia/Shanghai`）统一设置，启动日志会打印 JVM 时区、DB session 时区与 `NOW()` 偏差。
- MySQL 会话必须与应用同区：JDBC URL 使用 `connectionTimeZone=Asia/Shanghai&forceConnectionTimeZoneToSession=true`。
- `LocalDateTime` 的 REST/WS 序列化仍是数组（`[年,月,日,时,分,秒]`），前端统一用 `toDate()` 兼容；Trace JSONL 使用 ISO 字符串。
- 如果部署到 UTC 容器但漏掉上述 JDBC 参数，会出现 `NOW()` 比 Java 时间早 8 小时；`TimezoneConsistencyTest` 是回归护栏。

## 5. 单实例边界（当前版本）

以下状态在进程内，多实例部署会出现行为不一致：

- `WsSessionRegistry`：WS 在线会话在本进程；A 实例发送，B 实例上的接收者收不到实时帧。
- `GroupAgentRunRegistry`：同群 @AI 单飞/取消只在本实例生效。
- Trace writer 的 `pendingEvents/droppedCount` 是内存态。
- 定时任务（活动提醒、Trace 清理）每个实例都会跑；通知有 DB 唯一键兜底，但实时推送只到本实例。

生产如需多实例：需要 Redis Pub/Sub 或消息队列做 WS 广播、分布式锁做群 Agent 单飞/定时任务，或使用网关粘性会话。当前版本请按单实例部署。

## 6. 部署后 smoke

```bash
CAMPUS_API=http://localhost:8080/api \
SMOKE_USERNAME=<专用 smoke 账号> \
SMOKE_PASSWORD=<密码> \
node tools/verify-deploy-smoke.mjs
```

- L0 只读：登录、地图、通知 summary、日程、Trace 列表；并断言 `summary.total = 未读通知 + 有未读会话`。
- L1 可选：设置 `SMOKE_CONVERSATION_ID=<群会话ID>` 后，WS 同 `clientMsgId` 双发，断言 ACK 一真一重、历史仅一条；会写入一条 `[SMOKE]` 消息，请使用专用 smoke 群。
- 不要用生产真实用户/私聊做 smoke；脚本不会自动清理 L1 消息。

## 7. 回滚与排障

- 应用回滚：保留旧 jar，按迁移脚本只增不改的原则通常可回滚应用；不要回滚已执行的 `ALTER TABLE`，除非有备份。
- 启动失败先看 `SchemaPreconditionChecker` 的迁移提示；再看 JVM/DB 时区诊断。
- WS 不推：先确认单实例、`/ws` 代理 Upgrade、JWT query token；持久通知仍可在 `/messages` 查询。
- 真实 LLM/高德失败：检查 `DASHSCOPE_API_KEY` / `AMAP_WEB_KEY`；无高德 key 时路线会降级为 `ESTIMATED`，不是数据错误。
