# 第四轮 Agent 质量与性能评测报告（2026-10-22）

## 口径

- 模型：qwen-plus（DashScope OpenAI 兼容）；路线：高德 Web 服务。
- 机器：Windows 10 单机，后端单实例，MySQL/Redis 本地；测试数据来自 `seed-demo.mjs`。
- 每个场景默认 3 次；所有 Token 为 Trace `run/metrics.totalTokens` 汇总。
- 这是**单环境、小样本**对照，不能把百分比外推为线上 SLA；重点是验证评测链路可重复、指标可取证。

| 指标 | 值 |
|---|---|
| 硬运行 | 13/13 PASS |
| p50 / p95 | 26,052ms / 40,108ms |
| Token 合计 | 469,264（13 次） |
| 每场景 | S1 3/3、S2 3/3、S3 3/3、S4 3/3、S6 PASS |

| 质量门禁 | 约束状态、来源、站点数、交通总时长、冲突/UNKNOWN、跨群来源、Trace 完整 |

结论：在固定场景下，系统能稳定产出经过确定性校验、可保存的群活动计划。

## E2 效率开关 on/off

| 臂 | 运行 | 通过 | Token 平均 | 轮次平均 | 工具平均 | 耗时平均 |
|---|---|---|---|---|---|---|
| off（默认） | S1 ×3 | 3/3 | 33,817 | 6.0 | 5.0 | 23.4s |
| on（`campus.ai.efficiency.enabled=true`） | S1 ×3 | 3/3 | 29,565 | 5.0 | 5.0 | 32.5s |

- Token **−12.6%**、轮次 **−1.0**；本样本耗时反而增加 39%，与模型采样/网络波动混杂，不能得出“更快”的结论。
- 质量未退化（3/3 FEASIBLE、AMAP、2 站）。
- 原始数据：`raw/f3-efficiency-on.jsonl.summary.json`。

## E3 冷/热路线缓存

| 臂 | 运行 | Token | 轮次 | 工具 | 耗时 |
|---|---|---|---|---|---|
| 冷缓存（清空 `ai:route:*` 后首跑） | S1 ×1 | 31,115 | 6 | 5 | 33.9s |
| 热缓存（同场景立即再跑） | S1 ×1 | 12,230 | 2 | 1 | 22.4s |

- 热缓存 Token **−60.7%**、工具 **−4**、耗时 **−34%**；这是缓存与模型路径共同作用，不能全部归因于 Redis。
- 两臂均 1/1 通过，质量一致。
- 原始数据：`raw/f3-cache-cold.jsonl.summary.json`、`raw/f3-cache-warm.jsonl.summary.json`。

## E4 规划质量消融

| 臂 | 运行 | 通过 | Token 平均 | 轮次 | 结果 |
|---|---|---|---|---|---|
| full | S1 ×3 | 3/3 | 33,817 | 6.0 | FEASIBLE + GROUP_MAP + AMAP |
| `no-planner`（移除 plan_itinerary） | S1 ×3 | 3/3 | 24,819 | 5.0 | FEASIBLE + GROUP_MAP + AMAP |
| `no-group-map`（移除群地图工具） | S1 ×3 | **0/3** | — | — | 无草稿 |

- `no-planner` 在这个简单两站场景仍能靠模型自查通过硬校验，Token **−26.6%**；这**不能证明**复杂场景等价，长链多站仍需确定性求解器。
- `no-group-map` 完全无法产出可保存草稿，说明共建地图工具对“使用本群地点”是必要条件。
- 原始数据：`raw/f3-ablation-no-planner.jsonl.summary.json`、`raw/f3-ablation-no-group-map.jsonl.summary.json`。

## E5 确定性求解器重复性

- `SpatiotemporalPlannerTest.sameInputIsDeterministicAcross50Runs`：同一输入连续 50 次，Top-1 的站点时间、总交通、缓冲、评分、路线置信度、分段索引/耗时完全一致。
- 对比：真实 LLM 端到端 13 次虽然全部通过，但 Token/轮次/耗时存在明显波动（见 E1）。确定性核心与端到端方差的分离，是本项目“LLM 只编排、Java 判可行”的直接证据。

## 结论与边界

1. 真实 qwen-plus 在固定场景下能稳定产出 FEASIBLE/TENTATIVE/CONFLICT 三类可解释方案，且保存/幂等/409 闭环通过。
2. 建图工具与确定性求解器是关键能力：移除群地图工具后 0/3；移除求解器在简单场景尚可，但复杂场景不能据此宣称等价。
3. 路线缓存能把重复规划的成本显著压低，但热缓存结果依赖相同起止点；评测必须记录冷/热状态。
4. 单环境、N=3/单次对照、外部模型/高德波动，是本报告的主要限制；比赛答辩引用时应同时给出 N 与范围，而非只引用最好一次。
