## 第一幕：共享地图 = 团队的空间记忆

**账号**：`demo01` → 顶栏「地图」→ `[DEMO] 周末去哪儿`

**操作**：

1. 打开地图，展示 6 个共建地点（东区图书馆、南门咖啡、西区运动场、一饭·二楼、快递驿站、校车站）；
2. 点开「东区图书馆」：备注、评论、地点聊天室；
3. 顶栏「消息 → 会话」：群聊与私聊都收在消息中心，未读数可见；
4. 点会话直接深链回地图群聊（`/maps/{mapId}?chat=1`）。

**口播**：地点收藏、备注和聊天记录构成团队可检索的空间记忆，不是单次对话的临时上下文。

## 第二幕：群体忙闲与隐私红线

**账号**：`demo01`（Map A）/ `demo08`（Map B）

**操作 A（授权可见）**：

1. `/activities` →「我的日程」→「忙闲共享」：展示 Map A/C 已授权；
2. 群规划时只看到“忙碌时段”，看不到日程标题/备注/坐标；
3. 终端执行 `node tools/verify-round3-scenarios.mjs`：
   - Map A 全员授权完整（第二轮 FEASIBLE 基线未被撤销）；
   - Map B 临时撤销 demo09 → `group-busy` 出现 UNKNOWN → 自动恢复。

**操作 B（UNKNOWN/TENTATIVE，使用 Map B）**：

1. 用 `demo08` 登录，在 `[DEMO] 社团活动策划` 群聊输入：
   `@AI 周三晚上我们排一个两小时招新碰头，地点从群地图里选`
2. 预期：若 demo09 临时未授权，卡片显示「暂定：含未授权忙闲成员」，成员列表有人标记 UNKNOWN；
   恢复授权后重跑，方案变为 FEASIBLE。
3. 不要永久撤销 Map A 的授权，避免破坏第二轮可行基线。

**口播**：未授权成员不会被当作“有空”；方案会明确降级为暂定，而不是编造成员空闲。

## 第三幕：群 @AI 时空联合规划 + 公开地图回放

**账号**：`demo01` + `demo02`/`demo03`（三账号）

**操作**：

1. `demo01` 在 Map A 群聊输入：
   `@AI 明天下午三点开始，两小时，从东区图书馆步行到南门咖啡，帮我们排一下`
2. 等待 30–240 秒：
   - 群聊出现「🤖 AI 正在规划」进度、工具数与耗时；
   - 完成后收到 AGENT 总结 + 规划卡片（站点时间线、交通耗时、忙闲覆盖）；
   - 若与成员日程冲突，卡片显示冲突成员与建议；必要时改时间重试。
3. 点卡片「查看完整方案」→ `/conversations/{id}/plans/{planId}`：
   - 地图只画公开站点；来自私人地图/不可核实的站点显示 🔒，不画点、不画相关路线；
   - 路线严格按原始相邻站点对绘制，A 公开、B 私有、C 公开时不会连 A→C；
   - 高德折线存在时图例「路线预览（高德实际路线）」；失败/缺失时虚线并标注「示意连线，非实际行走路线」。
4. 发起人点「继续规划」→ `/assistant` 编辑草稿 v2；「保存为活动」→ `/activities` 自动定位活动详情；
5. 保存后直接打开邀请弹窗，邀请 demo02/demo03。

**可复现脚本**：

```bash
node tools/verify-round2-real-llm.mjs   # 真实 LLM：@AI→卡片→保存→活动可读→Trace
node tools/phase-h-demo.mjs demoHX      # 场景 A–E（含冲突/UNKNOWN/指纹）
```

**口播**：LLM 只做意图理解与编排；共同空闲由 `FreeWindowSolver` 确定性求解，交通由高德真实耗时；保存前做群体二次校验，地图回放只使用公开站点。

## 第四幕：消息中心 + 三账号闭环

**账号**：`demo01`、`demo02`、`demo03`（三个独立浏览器 origin 或三台设备）

**流程**：

1. `demo02` 向 `demo03` 发好友申请（或直接用种子数据：demo01/02/03 已互为好友）；
2. `demo03` 顶栏「消息」出现角标 →「好友申请」接受；
3. `demo01` 在被邀请者离线时创建活动并邀请 `demo02`：
   - 离线期间通知已落 `notification` 收件箱；
   - `demo02` 登录后「消息 → 通知」能看到活动邀请，角标不重复计数（好友/邀请只做 tab 待办）；
4. 点通知 → `/activities?tab=invites` →「接受」；
5. 创建者 `demo01` 收到「成员加入」通知；活动成员变为 2 人；
6. 临近签到：创建 `start=now+5min` 的活动，demo02 在开始前 15 分钟内输 6 位码签到；
7. 打开群聊/私聊会自动清除会话未读（READ 回执刷新顶栏角标）；关闭浮层后新消息仍会在消息中心累计。

**口播**：持久收件箱保证离线可查；实时 WS 只是尽力投递，提交后崩溃也不丢收件箱记录。

## 固定场景与预期

| 场景 | 固定 prompt / 操作 | 预期 |
|---|---|---|
| 可行基线 | Map A：`@AI 明天下午三点开始，两小时，从东区图书馆步行到南门咖啡` | 草稿 FEASIBLE，站点/交通/停留齐全 |
| 时间冲突 | 把时间改到某成员已有日程的重叠窗口 | 保存/提交返回 409 或卡片标注冲突，不静默覆盖 |
| UNKNOWN/TENTATIVE | Map B：临时撤销 demo09 授权后 `@AI 周三晚上排两小时招新碰头` | 方案 TENTATIVE，demo09 标记 UNKNOWN；恢复授权后 FEASIBLE |
| 交通不可行 | 两站间隔 5 分钟但要求跨校区步行/驾车 | `PlanValidator` 拒绝，提示 `TRAVEL_TIME_CONFLICT` |
| 三账号邀请→签到 | demo01 邀请 demo02/03 → 接受 → 窗口内输码 | 成员数正确，签到记录 `checkedIn=true` |
| 离线通知 | demo02 离线时 demo01 邀请 | 登录后消息中心可见，不依赖 WS 补推 |
| 公开地图 | 非发起人打开方案详情 | 只看到公开站点与相邻公开路线，无私人坐标 |

## 演示注意事项

- 先跑 `seed-demo.mjs` 再跑 `demo-report.mjs --verify`；报告中的日程窗口是“未来 30 天”；
- 群 @AI 每群同一时间只允许一轮，取消必须带 `runId`；
- 演示前不要永久撤销 Map A 授权；UNKNOWN 场景用 Map B 并在脚本/演示后恢复；
- `--reset-demo` 默认只预览，确认后再加 `--apply`；
- 截图/录屏只使用 demo 数据，不要包含真实 token、私聊内容或私人日程标题。
