## 第一幕：让 AI 理解地点（群体地理记忆检索）

**操作（alice 账号）**：登录 → 共享地图「G 共享图」已含“东九草坪角 / 南门奶茶街口”两处收藏（演示用脚本或手工预置）。

**演示话术/接口**：`GET /api/maps/{id}/places` 直接展示地图与列表（也可在地图工作台点开地点抽屉）。

**能力展示**：群体共享地理空间——地点收藏即团队的地理记忆。

## 第二幕：让 AI 理解时间（多人时间协同 + 逐条隐私）

**操作**：alice 在「个人日程」给明天 13:00–14:00 记一条"组会占用"（PII 内容），并已对群组授出 FREE_BUSY；bob 打开群忙闲视图；未入群的 carol 同页对比。

**接口**：`GET /api/schedules/group-busy?groupId=&from=&to=`；alice 授权 `PUT /api/schedules/share {targetType:GROUP, grant:true}`。

**能力展示**：
- 授权成员看到的是**只有时段的忙闲**（title 恒为 null，不泄露"组会占用"字样）——FREE_BUSY 权限红线；
- 未授权成员**不视为有空**（unknownUserIds 显式列出），方案会被标注"暂定；
- bob 报名/创建的己活动也会计入忙碌（活动 ∪ 个人日程，去重交给区间求解器）。

## 第三幕：让 AI 协同规划并执行（跨业务可信执行）

**操作（alice）**：
1. 进入地图群聊（「G 共享图」的会话），输入：`@AI 周六下午我们什么时候都有空？帮我排一个两小时的小活动，地点优先用共享地图。`
2. 等待 30–90s：群聊收到 **🤖 AGENT 总结消息** + **AI 规划卡片**（AGENT_PLAN_CARD 帧，含站点时间线）。
3. 打开 `/assistant`（AI 助手）→ 恢复最近会话 → 看到相同草稿 → 点「✏️ 编辑」→ 改标题/站点时间 → 「应用修改（重校验）」→ v2 草稿。
4. 点「保存为活动」→ 跳 `/activities` 日历 → 活动详情含 stops 与站间交通；**再按一次保存**：幂等（同一 activityId，不重复建活动）。

**脚本化复现**：`node tools/phase-g-demo.mjs demoGX .ai-run/xxx.jsonl`（12 步自动验收：建图→授权→忙闲视图→@AI 卡片→修订→保存→幂等），最近一次全绿记录 `.ai-run/phase-g-demoG4.jsonl`。

**能力展示**：
- LLM 只负责意图理解与编排；时间窗口由确定性求解器（FreeWindowSolver）计算，路线由高德真实耗时（10 分钟缓存）；
- 未授权的成员忙闲不参与规划（群体 find_free_windows 返回 coverage/UNKNOWN，方案暂定）；
- 写入走「用户确认 → 二次校验（行锁 + 版本防覆盖）→ 事务创建活动 + stops」——防并发日程变化、防重复提交。

## 演示注意事项

- 群聊 @AI 触发后模型需 30–90s（≤14 轮工具循环），演示时口播"这是在真实调用高德与qwen";
- 第三幕依赖个人日程授权/活动数据——若演示库为全新库，先跑 `schema.sql`；
- AI_RUN 观测行（`grep AI_RUN` | 后端日志）可作为答辩加分项：展示每次规划的轮次/工具/token/耗时结构化记录。

## 第四幕（H 阶段补全）：群体共建地图驱动 + 时空联合规划（P0.5 / P1.5）

**操作（alice，A 群）**：
1. 提前在群地图给三个地点写备注：图书馆「适合安静学习」、栈咖啡「适合四个人讨论，带电脑很方便」、操场「适合运动」。
2. 群聊输入：`@AI 周六下午我们四个人讨论比赛项目，要能带电脑，从我们地图里找地方`
   → AI 应给出 **共建地点（咖啡）** 并引用群内备注原文（来源徽标「共建」；不听备注它命中的就是 POI）。可用
   `node tools/phase-h-demo.mjs demoH1` 复现场景 A。
3. 群聊输入：`@AI 周五下午帮我们排一次小组活动：下午三点开始，两小时，地点从我们地图里选`
   → 卡片出现 **时间线 + 逐站停留 + 站间交通耗时 + 忙闲覆盖说明 + 指纹（planningSourceVersion）**；
   时间是由 Java 确定性求解器算出的（口播强调不是模型猜的）。
4. 续聊：`@AI 把刚才的方案创建成周六下午的活动` → 「去 AI 助手确认」→ 保存为活动 → 再次保存幂等；
   若此时 Bob 的日程变动或地图变化，保存会被 409 拦下并要求重新确认（可信执行红线）。
5. 隔离展示（可选）：另一个群（carol 的群）里没有任何 Alice 群的地点或备注；
   Alice 群聊里 @AI 也永远提不到「B 群机密讨论室」。

**能力展示**：
- 共建地图作为 Agent 的空间记忆：备注语义参与检索与推荐依据（P0.5）；
- 来源可证：卡片/草稿 stops 带 GROUP_MAP/PERSONAL_MAP/AMAP_POI 标签，由后端按数据盖章写入，模型自述不算数；
- 确定性时空联合：共同空闲（FreeWindowSolver）+ 高德真实交通 + 站点停留 + 收尾缓冲（SpatiotemporalPlanner），
  「三小时排满三地点」这种方案直接被提交校验拒绝并说明原因；
- 规划指纹：共建地图/地点在规划期间变化，保存时 409 要求重新确认（planningSourceVersion）。

**评审修复后的口径更新（H→I 阶段）**：
- 已保存草稿的「编辑」保存默认**更新原活动**（卡片按钮为「保存并更新活动」）；要另建新活动点「🆕 另建新活动（复制草稿）」。
- 交通徽标：卡片显示「交通·高德实测」或「交通·估算（未验证）」（routeConfidence），估算方案要向评委明示。
- 冲突演示彩蛋：把活动开始时间改到成员相邻日程 10 分钟内或重叠窗口，保存会被 409 拦截并说明“衔接不足/时间冲突，请重新确认”。
- watchdog：`node tools/phase-h-demo.mjs 画面后缀` 场景 A–E 全绿（JSONL 存档），`node --check` 可先做语法闸。

## 第五幕（Trace P0）：一次规划到底发生了什么

**前置**：先执行 `db/migration/20261019_01__create_agent_trace.sql`；
后端开启 `campus.agent.trace.enabled=true`（默认开启）。

**演示顺序**：
1. 用户在 AI 助手里发送：
   `明天下午去图书馆复习两小时，之后和朋友在食堂吃饭，避开我已经报名的活动`
2. SSE 正常显示 Agent 工作过程；随后打开：
   `GET /api/agent/traces`（本人会话列表）→ 找到本次 `sessionId`。
3. `GET /api/agent/traces/{sessionId}/events?size=200`，按 `seq` 看到：
   - `session/start` → `turn/start` → `step/start`；
   - `llm/request` / `llm/response`（模型、耗时、Token；不展示 prompt 原文）；
   - `tool/call` / `tool/result`（`callId` 与模型 tool_call 一一对应，含地图/路线/忙闲摘要）；
   - `plan/validate`（通过或失败规则）；
   - `plan/draft`（草稿版本）。
4. 让第一版草稿出现“站间交通耗时超过间隔”冲突：`plan/validate` 出现
   `status=FAILED`、`errorCode=TRAVEL_TIME_CONFLICT`、`details.availableMinutes/requiredMinutes`。
5. 让 Agent 修正并提交 v2，校验通过后用户确认保存：
   - `plan/confirm`（SUCCESS）→ `activity/created`（activityId）→ `session/end`（COMPLETED）；
   - 再点一次保存：`plan/confirm` 出现 `idempotentReuse=true`，活动 ID 不变。
6. 打开页面顶栏「执行追踪」（`/traces`）：
   - 左侧会话列表展示状态/耗时/Token/工具数/完整性；
   - 点进会话查看 Turn/Step 时间线、工具 `callId`、草稿 v1→冲突→v2→确认、活动 ID；
   - 右上角「导出 JSONL」下载，首行 `trace/meta` 的 `complete=true`；
   - 也可直接调 `GET /api/agent/traces/{sessionId}/export?format=jsonl`，
     或使用 `docs/agent-trace/sample-session.jsonl` 做离线讲解。
7. 异常展示（可选）：断开浏览器/取消一轮，`turn/end` 显示 `CANCELLED`，
   `stream/close.cancelled=true`，**不会**伪装成成功或 `activity/created`。

**口播要点**：
- 追踪由 Spring Boot 在真实执行点自动记录，模型不写日志；
- `callId` 关联请求/响应，`seq` 行锁保证同会话唯一，Trace 写入失败不影响主业务；
- 只存脱敏摘要：没有聊天原文、地点名/地址/备注、精确坐标、JWT/API Key；
- 保存成功只在事务提交后记录，回滚绝不出现 `activity/created`。
