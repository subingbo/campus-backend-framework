# 4B · 消息中心

- 日期：2026-10-23
- 范围：通知、会话、好友申请、活动邀请四分区；不改 API/WS/summary 语义
- 证据：1440 / 390 / 375 / 375 长文本

## 改动

- 使用 `PageHeader`：标题、说明、右侧未读总 pill；移除旧 hero/蓝 tag。
- 四个 `el-tabs` 保留原有 tab 值、懒加载和键盘语义；计数改用 `ui-count`。
- 通知范围「全部/未读」改用 `ui-chip`；「全部已读」改文字动作。
- 通知、会话、申请、邀请统一无阴影连续行 + 发丝分隔；未读行 accent-tint + 小圆点；长标题在 375 换行、摘要两行截断、操作不被挤出。
- 通知行主区域是独立 `.message-row__open` button，「标记已读」是兄弟按钮，避免嵌套 button；会话行整行是 button。
- 四分区分别有 loading / error + 重试 / empty；失败保留旧数据，不再只 toast 后显示“暂无”。
- 请求加序号保护（旧响应不覆盖新筛选）；接受/拒绝/已读/全部已读按类型+ID 做 pending 禁用。
- 保留：summary 服务端语义、markRead 先读后跳、markAllRead 双刷新、好友接受连带会话、邀请接受/拒绝连带通知、WS on/off、`?tab=invites` 深链。

## 实测

| 项目 | 结果 |
|---|---|
| 四 Tab | 通知 3 / 会话 / 好友申请 1 / 活动邀请，均可达 |
| 未读筛选 | 切到未读后 chip 激活，通知列表按 unreadOnly 重拉 |
| 通知失败注入 | 显示 `Network Error` + 重试；其它分区仍可加载 |
| 重试 | 解除拦截后点击重试，通知行恢复 |
| 1440/390/375 | 无横向滚动；375 四 Tab 同屏 |
| 375 长标题/长摘要 | 标题换行、摘要两行截断，「标记已读」仍在屏内 |
| build / test | build 通过；50/50 |

## 未做/边界

- 为避免改动演示账号数据，本轮未点击接受/拒绝/标记已读/全部已读这些会写入服务器的动作；pending 与失败保留逻辑做了代码审查。
- 会话/好友申请/邀请的独立失败未逐个注入；通知失败已覆盖同一套状态结构。
- 错误注入时 summary 请求也被拦截，因此截图/日志中的计数暂时消失，属于测试方式，不是页面缺陷。
