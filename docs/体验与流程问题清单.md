## 一页结论

你感觉“用起来有点不顺”，主要来自 5 个根因：

1. **概念混用**：“活动”“我的日程”“个人日程”“规划/计划/草稿”在界面上没有分清。
2. **入口隐藏或分散**：群聊 `@AI` 没有按钮；活动操作散在 7 处；聊天入口 5 处；活动邀请埋在“成员”展开里。
3. **关键步骤缺反馈**：群 @AI 执行期间无进度；WS 断线静默丢消息；报名/取消/拒绝好友反馈弱。
4. **断线与过期处理缺失**：WS 断开不提示、不重试；token 30 分钟过期没有刷新，直接踢回登录。
5. **前后端能力不对齐**：个人日程后端有完整 CRUD，前端没有入口；“我的日程”页面实际是“我的活动 + 忙闲开关”。

下面按 P0（先修）、P1（明显摩擦）、P2（边界优化）和技术风险附录展开。

## 二、P0：最影响使用的 5 个问题

### P0-1 “我的日程”名不副实，个人日程没有前端入口

- **现象**：`/activities` 的「我的日程」tab 实际展示的是“我报名/我创建的活动”分组和忙闲共享开关，没有个人日程列表，也没有新增/编辑/删除按钮。
- **证据**：
  - `campus-web/src/views/ActivitiesView.vue:47-105`：tab 内容只有忙闲共享 + `ActivityEntryCard` 活动列表。
  - `campus-web/src/api/index.js:48-51`：`scheduleApi` 只封装了 `shareOptions`/`setShare`，没有 `list/create/update/delete`。
  - 后端其实已有完整 CRUD：`campus-server/.../schedule/controller/ScheduleController.java:38-63`。
- **影响**：用户无法添加课程/会议/自习等个人日程；忙闲共享的数据源不完整；AI 规划只能看到活动占用；用户会以为“日程坏了”。
- **建议**：二选一，优先 A：
  - A. 在「我的日程」增加个人日程列表 + 新建/编辑/删除，并接入 `GET/POST/PUT/DELETE /api/schedules`；
  - B. 暂时把 tab 改名为「我的活动」，另开「个人日程」入口，避免误导。
- **验收**：新建一条个人日程后，列表可见、可编辑/删除；忙闲共享开关打开后，群 `group-busy` 能看到该时段。

### P0-2 群聊 @AI 是隐藏的“魔法前缀”，执行期间无反馈

- **现象**：群聊输入框只有“输入消息，Enter 发送”，没有“问 AI 规划”按钮或提示；必须手打 `@AI` 开头才会触发。执行期间没有“正在规划/已调用工具”状态，用户容易重复发送或以为坏了。
- **证据**：
  - `campus-web/src/components/ChatPanel.vue:86`：输入框 placeholder 只有“输入消息，Enter 发送”。
  - `campus-server/.../ai/service/GroupAgentService.java:44,68-72`：只识别 GROUP 会话 + `startsWith("@AI")`。
  - `ChatPanel.vue:196-200`：只在结束后处理 `AGENT_PLAN_CARD`；没有中间状态。
- **影响**：用户不知道有这个能力；地点聊天/私聊同样有输入框但不会触发，进一步造成困惑。
- **建议**：
  - 群聊输入区加「问 AI 规划」按钮，点击后自动插入 `@AI `；
  - 执行中显示“AI 正在规划（已调用 X 个工具）”并可取消；
  - 地点聊天/私聊明确提示“仅地图群聊支持 @AI”。
- **验收**：不手打 @AI 也能发起规划；执行中能看到状态；重复点击不会重复创建任务。

### P0-3 群规划卡只能看，非发起人无法保存，核心任务断链

- **现象**：群聊里的 `AGENT_PLAN_CARD` 只读，提示“到页面顶部 AI 助手可编辑并保存”；但群 AI 会话归属发起人，其他成员在 `/assistant` 找不到这份草稿，也没有保存入口。
- **证据**：
  - `campus-web/src/components/ChatPanel.vue:74-76`：卡片提示去 AI 助手编辑，但没有按钮。
  - `campus-server/.../ai/service/GroupAgentService.java:88-89`：每次群 @AI 新建 `ai_conversation`，归属发起人。
  - `AssistantController.java` 的会话列表/详情/保存按 `requireOwned` 限制。
- **影响**：发起人要离开群聊去找会话；其他成员被引导到 AI 助手却永远找不到草稿；“群聊里生成计划 → 变成活动”的核心任务断链。
- **建议**：
  - 群卡片直接提供「编辑」「保存为活动」；或
  - 卡片明确显示“由 XX 发起，仅发起人可保存”，并提供“让发起人继续”的提示；
  - 若允许非发起人保存，需要新增群权限校验的卡片级保存接口。
- **验收**：发起人可在群卡片或一键跳转后完成保存；非发起人不会看到无效入口。

### P0-4 WebSocket 断线时发送被静默丢弃，草稿已清空

- **现象**：弱网/后端重启时点发送，输入框清空、消息消失、没有错误提示；用户以为发送成功。
- **证据**：
  - `campus-web/src/components/ChatPanel.vue:224-230`：先 `draft.value = ''`，再 `send(...)`。
  - `campus-web/src/composables/useChatSocket.js:102-106`：socket 非 OPEN 时直接 `return`，不报错。
  - 连接状态 `connected` 没有被任何页面消费。
- **影响**：消息丢失且不可恢复，用户重复输入；弱网体验很差。
- **建议**：发送前检查连接；消息进入“发送中/失败可重试”队列；顶栏显示“已断开，正在重连”；失败时保留草稿。
- **验收**：断开 socket 后点发送，输入框不清空、有明确失败提示、重连后可重试。

### P0-5 Token 30 分钟过期无刷新，长任务中途被踢回登录

- **现象**：AI 规划、填活动表单、聊天时可能突然跳回登录页，未保存内容丢失。
- **证据**：
  - `campus-server/src/main/resources/application-dev.yml:26`：`access-token-expiration: 1800`（30 分钟）。
  - `campus-web/src/api/http.js:24-33`：401 时清空 token 并 `window.location.href='/login'`；没有 refresh 调用。
  - 登录时已保存 `refreshToken`（`LoginView.vue:63-64`），但前端从未使用。
- **影响**：长任务（AI 60-150 秒、活动表单）容易中断；用户对“突然退出”非常敏感。
- **建议**：实现 refresh 或静默续期；过期前提示；跳转前把 AI 草稿/活动表单缓存到 localStorage，登录后恢复。
- **验收**：access token 过期后，发请求能自动刷新并继续；不再硬跳登录。

## 五、技术风险附录（不改代码，但必须知道）

> 这些不是“界面不顺”，而是数据/权限/隐私层面的隐患。按影响排序。

### 5.1 高优先级

| ID | 问题 | 证据 | 影响 |
|---|---|---|---|
| T1 | `GET /schedules/group-busy` 不校验查看者是否该群成员 | `ScheduleService.groupBusy` 只按 groupId 取成员/忙闲，没有 viewer 成员校验 | 知道 groupId 的任何登录用户都能读已授权成员的忙碌时段 |

| T4 | 移除地图成员后 `conversation_member` 残留 | `ConversationServiceImpl.syncMapMembers` 只增不减 | 被移除者仍看到会话条目，点进去 403 |
| T5 | AI 已保存后再发消息会清空 `saved_activity_id`/谱系 | `AiConversationMapper.updatePlanResult` + `AgentService.handleSubmitPlan` | 用户以为改同一活动，实际再保存会新建重复活动 |
| T6 | AI 往返方案的“起点”可能被保存成正式地点 | `SpatiotemporalPlanner` 起点 `placeId=null`；`PlanSaveService.ensurePlace` 会创建 place | 用户实时位置被落库成“出发点”地点，隐私与数据污染 |
| T7 | 手动创建活动与 AI 保存校验口径不同 | `ActivityServiceImpl.create/saveStops` vs `PlanValidator` | 同一活动经不同入口质量不一致 |
| T8 | 取消活动后详情 404 | `mine` 返回 CANCELLED，`GET /activities/{id}` 404 | 日程页点进已取消活动失败 |

### 5.2 中优先级

| ID | 问题 | 证据 |
|---|---|---|
| T9 | 报名先 count 后 insert，无锁，可能超员 | `ActivityServiceImpl.join` |
| T10 | 取消报名硬删成员行，签到记录丢失 | `ActivityServiceImpl.leave` |
| T11 | 待响应邀请在活动取消后仍出现，接受时才报错 | `ActivityInviteMapper` + `cancel` 不处理邀请 |
| T12 | 拒绝后无法再次邀请（唯一键 + 任意状态 exists） | `ActivityServiceImpl.invite` |
| T13 | 签到码 6 位明文、可 10 次/分钟暴力尝试 | `activity.checkin_code` + 签到接口 |
| T14 | 活动/地点 WS 通知在事务提交前发出 | `ActivityEventNotifier`、`MapEventNotifier` |
| T15 | 地图内新增地点没有 5 米格网锁 | `SharedMapServiceImpl.addPlaceToMap` |
| T16 | 群/地图无删除/退出/转让接口 | `SharedMapController` |
| T17 | 邀请码永久有效、入群即 EDITOR | `SharedMapServiceImpl.joinGroup` |

### 5.3 需要产品先确认的语义

1. 群活动是否要持久关联群，并在保存后通知/邀请群成员？
2. 群卡片是否允许非发起人保存？若允许，权限模型怎么定？
3. AI 已保存后再对话，应该更新原活动还是新建？当前是新建。
4. `asNewDraft` 是“复制新会话”还是“同一会话再建活动”？当前是后者。
5. 签到窗口权威口径：`[start, start+15]` 还是 `[start-15, start+15]`？代码是后者。
6. `USER` 级 FREE_BUSY 是否要真正支持？当前无读取入口。
7. 撤销 FREE_BUSY 后，历史 plan/AGENT/Trace 是否要脱敏/擦除？
8. 手动活动是否要与 AI 保存共用同一套校验？
9. 坐标统一 GCJ-02：`place` 表注释仍写 WGS84，需要确认历史数据。
10. Redis 不可用时产品降级策略：401/限流放行/缓存跳过/未读延后？
11. 取消活动详情是否应可访问？当前 404。
12. 多实例部署是否近期要做？WS 在线态、Trace 锁、提醒都按单实例假设。

## 六、推荐修复路线

### 第一步：体验止血（优先做）

1. 个人日程入口/或把「我的日程」改名为「我的活动」。
2. 群聊 @AI 按钮 + 执行进度/取消。
3. 群卡片可编辑/保存，或明确“仅发起人”。
4. WS 发送状态 + 断线保留草稿 + 重连提示。
5. token 静默刷新；401 前缓存表单/草稿。

### 第二步：入口整合

1. 统一活动详情（日历、我的日程、地图浮窗都指向同一处）。
2. 全局聊天抽屉 + 未读角标。
3. 统一个人/群计划卡组件，统一“编辑/保存/去授权/查看执行过程”。
4. 忙闲未授权就地授权。
5. 角色/术语统一字典。

### 第三步：数据一致性

1. `group-busy` 增加群成员校验。
2. conversation 增加 `map_id/place_id` 唯一约束或并发幂等。
3. 移除成员时同步清理 `conversation_member`。
4. FREE_BUSY 撤销后的历史脱敏策略。
5. AI 谱系/另存语义定稿；起点位置不落库。
6. 活动取消/报名/签到/邀请的生命周期规则统一。
