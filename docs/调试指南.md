# 调试指南

> 面向本地开发与演示：怎么启动、用哪个账号、到哪里看群聊/地图/日程、怎么查接口和数据库、常见坑。
> 账号与数据总表见 [`demo-accounts.md`](./demo-accounts.md)；由脚本生成的完整明细见 [`演示账号与数据总表.md`](./演示账号与数据总表.md)。

## 1. 启动与访问

按顺序执行（仓库根目录）：

```bash
# 1) MySQL 8 + Redis 7
docker compose up -d

# 2) 后端（多模块工程，必须带 -pl campus-server -am）
mvn -pl campus-server -am spring-boot:run

# 3) 前端（另开终端）
npm --prefix campus-web run dev
```

| 入口 | 地址 | 说明 |
|---|---|---|
| 前端 | http://localhost:5173/ | **必须用 localhost**；`127.0.0.1:5173` 可能打开别的项目 |
| 后端 | http://localhost:8080 | Vite 已把 `/api`、`/ws` 代理到 8080 |
| Swagger | http://localhost:8080/swagger-ui.html | 分组「脚手架基础设施 / 校园业务」 |
| 执行追踪 | http://localhost:5173/traces | Agent 工具调用、耗时、错误码 |

内存紧张时（本机常见）后端可加小堆参数：

```bash
MAVEN_OPTS="-Xmx512m" mvn -pl campus-server -am spring-boot:run \
  -Dspring-boot.run.jvmArguments="-Xms128m -Xmx768m"
```

改了后端代码必须重启（旧实例不会热加载）：

```bash
netstat -ano | findstr :8080      # 找 PID
taskkill //F //PID <pid>
```

| 用途 | 账号 | 密码 |
|---|---|---|
| 管理端 | `admin` | `admin123` |
| 演示账号 | `demo01`–`demo20` | `demo1234` |

- 登录页：http://localhost:5173/login
- 切换账号：顶栏右侧「退出」→ 回登录页输入另一个账号。前端没有账号选择器，只能手工输入。
- 同一浏览器 localStorage 只能保存一个身份；想同时在线两个账号，用另一个浏览器/无痕窗口，或用 `curl`/脚本走 REST（见第 5 节）。

账号完整密码与每人地图/群聊/日程/忙闲授权/好友见 [`demo-accounts.md`](./demo-accounts.md)。

## 3. 功能入口与看什么

| 路由 | 页面 | 可验证内容 |
|---|---|---|
| `/` | 我的地图 | 当前账号加入的地图；不同账号看到的地图不同 |
| `/maps/:id` | 地图工作区 | 地点、地点评论、成员与角色、群聊消息、地图内活动 |
| `/friends` | 好友 | 好友列表、待处理申请、私聊入口 |
| `/activities` | 活动日程 | 活动列表、我的日程、忙闲共享开关 |
| `/assistant` | AI 助手 | 个人助手会话、规划草稿、保存为活动 |
| `/traces` | 执行追踪 | Agent 每次工具调用、耗时、token、错误 |

演示顺序建议：

1. `demo01` 登录 → 看 Map A（地点/评论/成员）→ 群聊 → 活动 → 好友/私聊。
2. 切换 `demo08` 看 Map B；切换 `demo15` 看 PUBLIC 的 Map C。
3. 用 `demo07`（VIEWER）确认不能编辑；用 `demo04` 发起/查看好友申请。
4. 群聊输入 `@AI` 开头的问题触发 Agent（会真实调用模型/高德，按需使用）。
5. AI 调完之后打开 `/traces` 看本次执行的工具链与耗时。

## 4. 造数与重新生成总表

```bash
# 补齐/创建演示数据（幂等、非破坏，只操作 demo01–demo20 与 [DEMO] 命名空间）
node tools/seed-demo.mjs

# 只校验不写入（含忙闲授权校验）
node tools/seed-demo.mjs --verify-only

# 只读导出账号/地图/日程/授权 Markdown 表
node tools/demo-report.mjs

# 校验每个账号都有地图、≥2 条未来日程、群忙闲授权
node tools/demo-report.mjs --verify

# 写到文件
node tools/demo-report.mjs --out "docs/演示账号与数据总表.md"
```

说明：

- 日程标题带 `MM-DD`，**跨周重跑会生成新的未来日程**；旧日程留在库里但默认窗口（未来 30 天）看不到。
- 脚本不会发送 `@AI`，不调用 LLM/高德；AI 相关数据需要现场操作产生。
- 消息只能走 WebSocket，脚本按内容去重，因此同一段文字不能作为两条不同消息存在。

## 5. 用接口调试

本机有 `HTTP_PROXY/HTTPS_PROXY`，访问 localhost 必须加 `--noproxy '*'`，否则可能 502。

```bash
# 登录拿 token
curl -s --noproxy '*' -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo01","password":"demo1234"}'

# 我的地图
curl -s --noproxy '*' http://localhost:8080/api/maps \
  -H 'Authorization: Bearer <accessToken>'

# 我的日程（默认未来 30 天）
curl -s --noproxy '*' http://localhost:8080/api/schedules \
  -H 'Authorization: Bearer <accessToken>'

# 我的群忙闲授权选项
curl -s --noproxy '*' http://localhost:8080/api/schedules/share \
  -H 'Authorization: Bearer <accessToken>'

# 群聊消息（需要该地图的 GROUP 会话 id）
curl -s --noproxy '*' "http://localhost:8080/api/conversations/28/messages?limit=50" \
  -H 'Authorization: Bearer <accessToken>'
```

注意：

- Git Bash 里 `curl -d` 的中文可能被编码破坏，请求体尽量用 ASCII 或 `\uXXXX` 转义。
- 消息发送没有 REST 接口，只能走 `ws://localhost:8080/ws?token=<accessToken>` 的 `CHAT_SEND` 帧。
- 登录限流 10 次/分钟/IP；脚本通过不同 `X-Forwarded-For` 规避。

## 6. 直接查库

MySQL 容器：`campus-mysql`，库 `campus`，账号 `root/root123`（compose 里配置）。

```bash
# 用户 → 地图/群聊/角色
docker exec campus-mysql mysql -uroot -proot123 campus -e "
SELECT u.id, u.username, u.nickname, g.name AS group_name,
       m.name AS map_name, mm.role
FROM sys_user u
LEFT JOIN map_member mm ON mm.user_id = u.id
LEFT JOIN shared_map m  ON m.id = mm.map_id
LEFT JOIN campus_group g ON g.id = m.group_id
WHERE u.username LIKE 'demo%'
ORDER BY u.username, m.id;"

# 用户 → 个人日程
docker exec campus-mysql mysql -uroot -proot123 campus -e "
SELECT u.username, s.title, s.start_time, s.end_time
FROM sys_user u
LEFT JOIN personal_schedule s ON s.user_id = u.id
WHERE u.username LIKE 'demo%'
ORDER BY u.username, s.start_time;"

# FREE_BUSY 授权
docker exec campus-mysql mysql -uroot -proot123 campus -e "
SELECT ou.username AS owner, g.name AS group_name, p.permission_level
FROM schedule_share_permission p
JOIN sys_user ou ON ou.id = p.owner_user_id
LEFT JOIN campus_group g ON p.target_type='GROUP' AND g.id = p.target_id
ORDER BY ou.username;"
```

关键口径：

- **群成员权威表是 `map_member`**，不是 `conversation_member`；后者只决定会话列表是否可见。
- 群聊是 `conversation(type='GROUP').map_id -> shared_map.id`，与 `campus_group` 1:1。
- GROUP 会话是**懒创建**的：没人打开过群聊时库里可能没有 conversation 行（演示数据已确保创建）。
- 密码是 BCrypt 哈希，不能直接改库成明文；新增账号走 `POST /api/auth/register`。
- 忙闲 = `personal_schedule` ∪ 已报名/已创建活动，不复制存储；`FREE_BUSY` 只共享时段，标题对他人为 null。

## 7. 常见坑

1. **端口被旧实例占用**：8080 有旧后端时先杀进程再重启；Vite 端口会递增（5173→5174…），遗留端口可能是僵尸（LISTENING 但 502）。
2. **localhost 与 127.0.0.1 不是同一个前端**：本机 Vite 可能只绑 IPv6，`localhost:5173` 才是本项目。
3. **时间字段是数组**：HTTP 响应里 `LocalDateTime` 可能序列化成 `[年,月,日,时,分,秒]`，前端/脚本都要兼容；`tools/demo-report.mjs` 已处理。
4. **VIEWER 只读**：`demo07`、`demo20` 不能加地点/发消息以外的写操作，看到按钮不可用是预期行为。
5. **群聊消息只能 WS**：用 Swagger 找不到发消息接口是正常的。
6. **`mvn -pl campus-server test` 必须带 `-am`**，否则会解析本地仓库旧构件出现假编译错；全量测试约 15–25 分钟，跑测试前先停后端，避免抢资源和 `target/classes` 冲突。
7. **Docker 引擎异常**：Testcontainers 相关验收测试会失败/跳过，先 `docker ps` 确认引擎，再判断是否代码回归。
