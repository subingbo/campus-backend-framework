## 2. 已完成工作

### 2.1 数据层与迁移

新增表：

- `agent_trace_session`：会话归属、conversation/draft/map/group 关联、状态、耗时、Token 汇总、事件/工具/错误/丢失计数、`next_seq`；
- `agent_trace_event`：`session_id + seq` 唯一、`trace_id`、事件类型、发生时间、turn/step、callId、状态、耗时、工具名、错误码、`payload_json`。

关键设计：

- `seq` 由 `agent_trace_session.next_seq` **行锁 + 独立事务**分配，避免多线程/多实例重复；
- Trace 写入使用 `REQUIRES_NEW`，业务事务回滚不影响追踪数据；
- `agent_trace_event.payload_json` 只保存 `TraceDataRedactor` 白名单脱敏后的摘要。

文件：

- `campus-server/src/main/resources/db/migration/20261019_01__create_agent_trace.sql`
- `campus-server/src/main/resources/db/schema.sql`
- `campus-server/src/test/resources/db/test-init.sql`

### 2.2 追踪核心与可靠性

- `AgentTraceWriter`：有界队列 + 单消费者；队列满时普通事件丢弃并计 `dropped_count`，关键终态同步 fallback；单条失败不杀死消费者；关闭时有限 drain。
- `JdbcTraceEventStore`：seq 分配、事件插入、计数更新、`session/end` 同事务更新会话、`trace/partial` 补记。
- `AgentTraceServiceImpl`：会话解析（RUNNING 复用；保存幂等复用 COMPLETED；其余新建）、turn 计数器、active run/pending finish、查询与导出。
- `TraceDataRedactor`：入队前白名单；秘密/正文/坐标/地点名剔除；工具入参/结果只留计数、ID、枚举、耗时。
- `AgentTraceCleanupJob`：陈旧 RUNNING 标 `INTERRUPTED` + `trace/partial`（不伪造 session/end）；`detail-days` 后分批删除。
- 配置：`campus.agent.trace.*`，默认开启，支持 OFF/SUMMARY/DEBUG（P0 DEBUG 不额外采集原文）。

### 2.3 业务埋点

| 位置 | 记录内容 |

| `AgentService` | `session/start`、`turn/start`、`step/start/end`、LLM request/response/error、tool call/result/error、stream open/close/error、终态 |
| `AgentToolkit` 调用包装 | `map/search`、`place/semantic-retrieval`、`route/estimate`、`schedule/free-window` 摘要；重复调用/搜索预算耗尽也有事件 |
| `PlanValidator` | 新增 `PlanValidationException`（稳定 ruleId + details）；`TRAVEL_TIME_CONFLICT` 记录可用/所需分钟、最早可设时间 |

| `AssistantController` | SSE 触发 `TraceTrigger.chat()`；保存/修订前预创建 trace session |

### 2.4 查询/导出 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/agent/traces` | 本人会话列表，分页/状态筛选 |
| GET | `/api/agent/traces/{sessionId}` | 详情（状态、Token、工具/错误/丢失数、complete） |
| GET | `/api/agent/traces/{sessionId}/events` | 事件分页，`seq ASC`，按 type/callId/step 筛选 |
| GET | `/api/agent/traces/{sessionId}/export?format=jsonl` | `application/x-ndjson` 流式导出，首行 `trace/meta` |

权限：仅本人可读；非本人/不存在统一 404；导出与列表同权限。  
`complete` 由服务端判定：`status == COMPLETED && dropped_count == 0`。

## 4. 已知限制与风险

1. **样例来自真实运行**：`sample-session.jsonl` 由真实 qwen-plus + 高德链路导出（2026-10-19，admin 会话，脱敏校验通过）；换演示环境时建议重新导出一份。
2. **`RUNNING` 会话不会自动成功结束**：用户只聊天不保存时，`turn/end` 记录终态，session 由清理任务在 `stale-running-minutes` 后标 INTERRUPTED；这是为了避免伪造成功。
3. **摘要不可回放**：P0 只保存安全摘要，无法还原完整 prompt/工具响应；P2 才做快照。
4. **测试 profile 特意放大参数**：`queue-capacity=10000`、`flush-timeout-ms=15000`，避免并发测试抖动；生产默认 2000/3000。
5. **MySQL 表缺失时 Trace 降级**：业务继续，但无追踪数据；启动/写入会限频告警。
6. **前端包体**：TraceCenterView 已路由懒加载为独立 chunk（22.5KB gzip 7.8KB）；主 chunk 仍 >500KB（element-plus + 高德 SDK），属既有工程问题。
